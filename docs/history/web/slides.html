This talk follows the web from its first page to today. It looks at four parts: HTML, CSS, scripts and servers. Each part has its own colour, and the next slide explains them. For each part we ask what it does, when it arrived, and how its job changed.

The colour key

Four parts, four jobs, four colours

HTML

The structure. It says what each part of the page is: a heading, a list, a link.

CSS

The look. It sets colours, fonts, spacing and layout.

Scripts

The behaviour. JavaScript runs in the visitor’s browser and changes the page.

Server

The computer that sends the page, runs programs and keeps the data.

Every slide after this one carries a coloured tag for each part it is about. Over thirty years, jobs moved between these four parts, and that movement is the story of the talk.

Ask the class to name a site they used today, and find each of the four parts in it. The colours stay the same for the whole talk: orange for HTML, blue for CSS, gold for scripts and green for the server. Each tag also carries its name, so nobody has to rely on the colour alone.

The S-curve: the total who have adopted so far

Before we start

How a new technology spreads

In 1962 the sociologist Everett Rogers described how new ideas spread through a group of people. A few innovators try something first. Early adopters follow, then the majority, and last of all the laggards.

Plot the total who have adopted so far, and you get an S-curve: slow, then steep, then flat.

Rogers set out these groups in Diffusion of Innovations, first published in 1962. The bell curve shows how many people adopt in each period. The S-curve adds them up. The percentages are idealised, and real technologies rarely follow the shape exactly, which the next slide shows. Every date in this talk marks a point near the start of a curve, not the moment everyone switched.

Chapter 1 · 1991 to 1995

Documents and forms

The web begins as pages of text and links, and forms let readers write back.

HTML

Server

Chapter 1 has two parts in play: HTML for the pages, and a server to send them and read forms.

1991

HTML

Server

The first page was text and links

Tim Berners-Lee put the first web page online at CERN. A page could not respond to anything except a click on a link. Each click asked the server for a whole new page.

That first page is still online, at info.cern.ch.

Browser

shows HTML

asks for a page

sends the whole page

Server

stores files

Each request brings back one whole page, and every website still starts this way.

The request and response on the right is the oldest pattern on the web, and it has never gone away. Every later idea in this talk is a way to do more without asking for a whole new page.

1993 to 1995

HTML

Server

Forms let readers write back

1

A visitor fills in a form on an HTML page and presses Send.

2

A program on the server reads what they typed. Early programs used a system called CGI.

3

The program builds a brand new page as its answer, and sends it back.

Forms became part of HTML 2.0 in 1995. Every answer, even “please fill in your email”, meant a trip to the server and a whole new page.

This is where the server becomes more than a file cabinet, because it now runs a program. Point out the cost of step 3. A small mistake on the form meant waiting for a new page just to hear about it. Scripts arrived partly to fix that, in chapter 2.

Chapter 2 · 1995 to 2004

Scripts, styles and server languages

Browsers and servers both learn to run programs, and plugins fill the gaps.

Scripts

CSS

Server

In chapter 2 every part except HTML gets something new. JavaScript and CSS arrive in the browser, and PHP and its relatives arrive on the server. The chapter ends by looking back at what we now call Web 1.0.

1995 and 1996

Scripts

CSS

Scripts and CSS arrive within a year

JavaScript, 1995

The Netscape browser added a language that runs inside the page. For the first time, a page could change without asking the server.

CSS, 1996

Style sheets moved colours and fonts out of the HTML. Browsers supported CSS unevenly for years, so many sites kept using tables and scripts.

Through the early 2000s, scripts did jobs that CSS does today: rollovers, opening and closing panels, checking forms and opening pop-up windows. Chapter 7 shows those jobs moving back.

The 1990s browser wars between Netscape and Internet Explorer meant each browser did things its own way. That is why so much early CSS was unreliable, and why scripts took over so many jobs. Hold on to that idea: jQuery in chapter 3 was built to cope with those differences.

1995 to 2005

Server

Servers learn to build pages from data

PHP was first released in 1995. A PHP file looks like HTML with small pieces of code inside. The server runs that code, fills in the gaps from a database, and sends plain HTML to the browser.

On the server

<p>Hello, <?php echo $name; ?></p>

What the browser receives

<p>Hello, Aoife</p>

PHP, 1995

Code mixed into the page itself

ASP, 1996

Microsoft’s version of the same idea

Ruby on Rails, 2004, and Django, 2005

Frameworks for Ruby and Python

WordPress, 2003

Written in PHP, and still behind a large share of sites

The browser never sees PHP. It only ever receives the HTML that the server built.

A common setup was called LAMP: Linux, Apache, MySQL and PHP. Each request runs the PHP again, so the same file can show a different page to every visitor. WordPress still works this way: when someone saves a post, PHP stores it in a database and builds the page from it each time someone visits.

1996 to 2020

Plugins

HTML

Plugins filled the gaps

A plugin is a program added to the browser to do what HTML could not. Flash was the best known. It played video, animation and games for over a decade.

2007

The first iPhone arrives without Flash.

2014

HTML5 adds <video> and <audio>, so a page can play a clip on its own.

2020

Flash reaches its official end in December.

Plugins are not one of our four parts, so their tag is grey. The story ends in HTML, which is why the 2014 step is orange. The lesson of Flash is that a feature built into HTML outlasts one added from outside. Plugins were also a frequent security risk, which helped speed their end.

Looking back

HTML

Roughly 1991 to 2004

Pages were mostly fixed documents, like a brochure.

Most visitors could read, but not add anything.

Layout was built from tables, and style was written into tags such as <font>.

Chapter 3 · 2005 to 2014

Web 2.0, HTML5 and every screen

Pages update without reloading, visitors write into the web, and HTML and CSS take on new jobs.

Scripts

HTML

CSS

Chapter 3 runs in order: Ajax in 2005, jQuery in 2006, Web 2.0, responsive design in 2010, HTML5 in 2014, and then a look at how CSS versions work.

2005

Scripts

Server

Ajax: update one part, not the whole page

The page

Inbox

The script puts a new message here

The rest stays still

“anything new?”

a little data, as JSON

Server

A script asks the server for a little data in the background, and changes one part of the page. Gmail in 2004 and Google Maps in 2005 made the idea famous. Today the script uses fetch, and the data usually travels as JSON.

Compare this with the first-page diagram in chapter 1, where every answer was a whole page. Here, only the gold part changes, and gold means a script did it. The name Ajax comes from a 2005 essay by Jesse James Garrett. Ajax is still a job for a script today, because HTML and CSS cannot fetch data on their own.

2006

Scripts

jQuery smooths over browser differences

In the 2000s each browser ran JavaScript a little differently. John Resig released jQuery in 2006. It gave one short way to write a script, and that script worked in every browser.

With jQuery, from 2006

$("#menu").slideToggle();
$.ajax({ url: "/news" });

Built into every browser now

document.querySelector("#menu");
fetch("/news");

Browsers now agree with each other, and they copied the best of jQuery’s ideas. New sites rarely need it, but many older sites still use it.

jQuery is a library: a ready-made set of functions written in JavaScript, which a page loads before its own script. It became one of the most widely used scripts on the web. Its story is the same pattern as Flash: once the browser can do the job itself, the add-on matters less. jQuery is still maintained today.

Web 2.0, from about 2004

Scripts

Server

Visitors start writing into the web

Comments and reviews

Anyone can add to a page, and the server stores it.

Social networks

The people are the content.

Wikis

Many people write one page together.

Pages that update

Ajax keeps the page fresh without reloading.

Web 2.0 is less a technology than a change in who makes the web. Its tools were scripts, servers and databases working together.

Three of the four ideas lean on the server, which stores what visitors write, so they carry green. Pages that update lean on scripts, so that one is gold. A good answer to “what changed with Web 2.0?” names a difference and gives an example of each. Wikipedia (2001) and Facebook (2004) are useful examples of Web 2.0. Tim O’Reilly’s 2005 essay gave the idea its name.

2007 to 2010

CSS

One page, every screen

Phones made fixed-width pages hard to read. In 2010 Ethan Marcotte named the answer responsive web design: one page whose layout changes to fit its screen.

It rests on three things: flexible layouts, flexible images, and CSS media queries.

A wide screen: three columns

A phone: one

The same HTML sits behind both screens, and only the CSS changes, which is why this slide is blue. A non-responsive page keeps one fixed layout, so a phone must zoom or scroll sideways. Also mention the older alternatives: an adaptive site switches between a few fixed layouts, and a separate mobile site serves different pages, often at an m. address.

2014

HTML

HTML5 gives HTML new jobs

What it added

  • Semantic tags: <header>, <nav>, <main>, <article>, <footer>
  • <video> and <audio>, in place of plugins
  • Form rules: required, type="email", pattern
  • <canvas>, for drawing with a script

What it retired, and CSS replaced

DeprecatedUse instead
<font>CSS font and color
<center>CSS text-align
<frame>CSS layout
<big>CSS font-size

A semantic tag says what its content is. Screen readers, search engines and the next person who edits the page all depend on that.

The deprecated table is useful for revision. Each retired tag described how text looked, and that job moved to CSS, so the right-hand card is blue. A deprecated tag may still work in a browser, but it is no longer part of the standard, and a validator flags it.

1996 to now

CSS

CSS versions: from three levels to many modules

CSS1

1996

Fonts, colours, margins and spacing.

CSS2

1998

Positioning, :hover, and styles for print.

CSS3

from about 2011

Split into modules: media queries, transitions, animations, flexbox, grid.

Now

no CSS4

Each module grows on its own. :has() and container queries arrived in 2023.

“CSS3” now means modern CSS in general. Each feature arrives when every major browser supports it.

The key point: after CSS2, CSS stopped having single numbered versions. It became a set of modules, each with its own level. This slide covers the whole span of CSS, so it reaches past chapter 3 into the present.

Chapter 4 · 2009 to now

Scripts grow up

JavaScript moves onto the server, frameworks build whole pages, and TypeScript adds types.

Scripts

Server

Chapter 4 overlaps chapter 3 in time. While HTML5 and responsive design were changing pages, JavaScript was turning from a small page language into one that runs whole applications.

2009

Scripts

Server

JavaScript moves onto the server

Browser

script.js

Server

server.js

Ryan Dahl released Node.js in 2009. Node runs JavaScript outside the browser, so a developer can write the page’s scripts and the server’s program in one language. Its package registry, npm, lets developers share small pieces of code with each other.

Both boxes carry a gold file, because the same language now runs at both ends. Until 2009 the server side of this diagram would have been PHP, Java, Python or Ruby. Anyone who has started a server.js file with the node command has already used it.

2010 to 2014

Scripts

Frameworks build whole pages in the browser

A framework builds the page from data inside the browser, and updates only the parts that change. A site built this way is called a single-page app, because the browser loads one page and the script does the rest.

AngularJS

2010, from Google

React

2013, from Facebook

Vue

2014, from Evan You

The cost is a large script to download before anything appears. Many sites now send ready-made HTML first, and add scripts only where they help.

Frameworks suit big applications such as email or maps, where the page changes all the time. They are heavy for a brochure site or a blog. The swing back to sending HTML first is the story of chapter 5 and chapter 7: let HTML and CSS do what they can, and use scripts for the rest. Nolan Lawson’s article in the notes shows what a framework does under the hood.

2012

Scripts

TypeScript adds types to JavaScript

Microsoft released TypeScript in 2012. A type says what kind of value something holds, such as a number or a piece of text. TypeScript checks the code against its types before it runs, then turns it into plain JavaScript for the browser.

function priceWithVat(
price: number
): number {
return price * 1.23;
}

priceWithVat("ten");

TypeScript stops at the last line before the code ever runs, because "ten" is text and not a number.

The browser still only runs JavaScript. TypeScript helps the person writing the code.

Types matter most on big projects with many people, where a wrong kind of value can travel a long way before anything breaks.

Chapter 5 · 2016 to 2022

The platform catches up

CSS gets real layout, every site gets a padlock, web apps work offline, and the browsers finally agree.

HTML

CSS

Scripts

Server

Chapter 5 is the quiet revolution. Few of these changes made headlines, but together they are why building a site in 2026 is so different from 2014. The chapter runs in order: the server returns in 2016, CSS Grid in 2017, offline web apps and WebAssembly, HTTPS everywhere, cookie banners and dark mode, the living standard in 2019, and the end of Internet Explorer in 2022.

2016 onwards

Server

Scripts

The server sends HTML first again

Server rendering

Next.js, released in 2016, builds a React page on the server, so the browser gets HTML it can show straight away.

Static site generators

Tools such as Hugo build every page once, ahead of time, and a host like GitHub Pages sends the files as they are.

Scripts where they help

The page arrives ready to read, and scripts wake up only the parts that need them.

The single-page apps of chapter 4 were slow to show anything. The answer was to go back to the oldest pattern on the web: the server sends a whole, finished page.

This closes a loop. Chapter 1 began with a server sending whole pages. Chapter 4 moved the work into the browser. From 2016 the work moved back to the server, now with modern tools. Anyone who publishes with GitHub Pages is already using a static site.

March 2017

CSS

CSS Grid: real layout at last

In March 2017, Chrome, Firefox and Safari all shipped CSS Grid within a few weeks of each other. For the first time, CSS could lay out rows and columns together. Twenty years of tables, floats and workarounds came to an end.

header

nav

main

footer

grid-template-areas:
"header header"
"nav main"
"footer footer";

Compare this with the 1996 and 2001 pages, which used tables for exactly this layout. Grid does the same job in CSS, so the HTML can stay semantic. Jen Simmons’s “Variations on a Grid” experiments from 2017 are good to show the class.

2015 to 2018

Scripts

Web pages start to behave like apps

Progressive web apps

A service worker is a script that sits between the page and the network. It can keep copies of files, so the site still opens offline. Add a small manifest file, and a phone lets you install the site on its home screen like an app.

Example: Squoosh, an image tool that works offline

WebAssembly, 2017

By November 2017 every major browser could run WebAssembly. It lets code written in languages such as C, C++ and Rust run inside a page at close to full speed.

Example: Figma, a design tool, runs in the browser this way

Both changes made the browser a place to run real applications, not just show documents. The term progressive web app was coined in 2015. Safari added service workers in 2018, which made offline sites work on iPhones too.

2015 to 2018

Server

Every site gets a padlock

Not secure

http://shop.example

https://shop.example

December 2015

Let’s Encrypt starts giving out free certificates, so any site can use HTTPS.

July 2018

Chrome begins marking every plain HTTP page as “Not secure”.

HTTPS encrypts everything between the browser and the server, so nobody on the same Wi-Fi can read or change it on the way.

Before free certificates, HTTPS cost money and effort, so only banks and shops used it. Many new browser features, including service workers, only work on HTTPS pages. Most hosts now give every site HTTPS for free.

2018 and 2019

Server

CSS

Cookie banners and dark mode

GDPR, May 2018

The EU’s data protection law began to apply on 25 May 2018. Sites that track visitors must ask first, and refusing has to be as easy as agreeing. The cookie banner became part of almost every page.

Dark mode, 2019

Phones and laptops gained a dark setting, and CSS gained a way to follow it. One media query lets a page pick its colours to match the device.

@media (prefers-color-scheme: dark)

Two very different changes, both visible on nearly every site today. The first came from a law, and it touches the server, which stores visitor data. The second came from operating systems, and it touches CSS. Ask the class how many cookie banners they clicked this week, and whether the Reject button was as easy to find as Accept.

2019

HTML

HTML stopped having version numbers

HTML is now one living standard that grows a feature at a time. Many of the jobs that scripts did in 2005 are now done by HTML and CSS alone.

This slide is orange because it is about HTML. The W3C and the WHATWG agreed in 2019 to keep one HTML standard, the HTML Living Standard. So “HTML5” is the last numbered version, and people still use the name for modern HTML in general. Chapter 7 shows which jobs moved.

2022

HTML

CSS

Scripts

The browsers finally agree

Internet Explorer retires

Microsoft retired Internet Explorer on 15 June 2022. For years, sites had carried extra code just to work in it.

Interop

Also in 2022, Apple, Google, Microsoft and Mozilla began Interop, a yearly project to make the same features work the same way in every browser.

The browser wars of chapter 2 made jQuery necessary. Interop is why the new HTML features in chapter 7 now arrive in every browser at about the same time.

This slide closes the story of browser differences that started in the 1990s. Interop publishes a public dashboard each year showing how well each browser scores on the agreed features, which students can look up at wpt.fyi.

Chapter 6 · 2023 to now

AI and the web

Machines start to write web pages, read them, summarise them and use them. The story is still being written.

HTML

Scripts

Server

This chapter is different from the others, because nobody knows yet how it ends. Present the facts and dates, then let the class argue. The discussion questions at the end of the chapter have no right answers. ChatGPT launched on 30 November 2022, so the chapter starts there in practice, but its effects on the web began to show in 2023.

November 2022 onwards

HTML

Scripts

AI starts writing the code

Chat assistants

ChatGPT launched on 30 November 2022. Within months, people were asking chat assistants to write whole pages of HTML, CSS and JavaScript from a description.

Assistants in the editor

Code assistants now sit inside editors such as VS Code. They suggest the next lines, explain errors and can change many files at once.

A generated page can look right and still be wrong: missing labels, broken headings, an unescaped form. Someone still has to read the code, run the validator and test it. That someone is you.

Keep this practical. The skills from earlier chapters matter more, not less, when a machine writes the first draft, because you have to check what it produced. A good class exercise: ask an assistant for a contact form, then run it through the W3C validator and an accessibility checker and count the problems.

May 2024

Server

Search starts answering for you

In May 2024, Google began showing AI Overviews in the United States: a written answer above the links. The answer is built from other people’s pages, and fewer searchers click through to read them.

how do I centre a div

AI overview

Set the parent to display: grid and add place-items: center.

mdn

css-tricks

Blue link 1 ↓

Blue link 2 ↓

Since 1998 the deal was simple: a search engine sent visitors to your site, and your site got the readers. An answer at the top of the page changes that deal. Ask the class: if nobody visits the site that wrote the answer, how does that site keep paying to exist?

1994, 2023 and 2025

Server

Who is allowed to read your site?

robots.txt

User-agent: GPTBot
Disallow: /

A file from 1994, at the root of a site, that asks robots to stay out. It is a request, not a lock.

August 2023

OpenAI publishes the name of its crawler, GPTBot, so sites can block it.

September 2024

A proposal called llms.txt suggests the opposite: a plain summary of a site, written for AI tools to read.

July 2025

Cloudflare starts blocking AI crawlers by default on new sites it protects.

robots.txt was proposed by Martijn Koster in 1994 and only became an internet standard, RFC 9309, in 2022. Well-behaved crawlers follow it; badly behaved ones ignore it, which is why Cloudflare blocks at the server instead. llms.txt is a proposal, not a standard, and few AI tools are known to read it.

2024 onwards

HTML

Some visitors are not people

AI agents can now open a page, read it, click buttons and fill in forms for a person. They read the HTML much as a screen reader does.

A real button, a labelled input and proper headings help a blind visitor, a search engine and an agent at the same time. A div pretending to be a button helps none of them.

Three tiers, three jobs

Presentation

HTML

CSS

Scripts

The client, which is the browser. It shows the page and sends requests.

Application

Server

The server’s program, in PHP, Node or Python. It checks each request and decides what to do.

Data

Server

A database server. It stores the data and answers many users at once.

Keeping the tiers apart means each one can be changed, secured or made bigger without rebuilding the others. A desktop database, by contrast, serves one person on one machine.

The application tier is sometimes called middleware. Walk a search through it: the visitor types in the browser, the application tier checks the request and asks the database, the database returns rows, and the application sends them back, often as JSON.

Keeping a dynamic site safe

Server

Scripts

The browser helps. The server protects.

SQL injection

An attacker types SQL into a form to change the query. The defence is a parameterised query, which keeps what they typed apart from the SQL.

Cross-site scripting

An attacker gets a script into a page that other visitors see. The defence is to escape output, so text never runs as code.

Passwords

Store a hash, never the password. A hash cannot be turned back into the password if the database leaks.

A form that checks itself with required and pattern helps the visitor. Anyone can bypass it, so the server must check every request again.

Two of the three attacks target the server and its database, so they are green. Cross-site scripting turns a page’s own scripts against its visitors, so it is gold. The last line matters most now that HTML does so much checking: browser checks are a convenience for the visitor, never a defence.
