A history of the web, from underneath

Down the Wire

How networks and protocols carried the web, and how each faster, wider pipe changed what a website could be.

Network

Server

Every page, script and database query travels over a network. This talk follows the wires, radios and rules that carry them, from a two-letter message in 1969 to 5G. The thread through it is simple: each time the pipe got wider or faster, websites changed shape to fill it.

Before we start

How a new technology spreads

In 1962 the sociologist Everett Rogers described how new ideas spread through a group of people. A few innovators try something first. Early adopters follow, then the majority, and last of all the laggards.

Plot the total who have adopted so far, and you get an S-curve: slow, then steep, then flat.

Rogers set out these groups in Diffusion of Innovations, first published in 1962. The bell curve shows how many people adopt in each period. The S-curve adds them up. The percentages are idealised, and real technologies rarely follow the shape exactly, which the next slide shows. Every date in this talk marks a point near the start of a curve, not the moment everyone switched.

Chapter 1 · 1969 to 1990

Packets find their way

Before the web, researchers built a network that could carry any message, by any route, between any computers.

Network

This chapter lays the ground every later chapter stands on: packets, addresses and names. None of it was built for the web, which arrived twenty years later.

29 October 1969

Network

The first message, and the idea of a packet

Packet switching

A message is cut into small packets. Each packet carries the address it is going to, and can take any free route there. The receiver puts them back in order.

HELLO → [H][E][L][L][O] → HELLO

The first message

On 29 October 1969 a student at UCLA tried to log in to a computer at Stanford Research Institute over ARPANET. The system crashed after two letters, so the first message was “LO”.

A telephone call holds one line open for the whole conversation. Packets share the lines, so a broken link only means a different route.

Leonard Kleinrock's lab at UCLA sent the message. The network was funded by ARPA, part of the US Department of Defense, and linked four universities by the end of 1969. Packet switching is why the internet survives broken links: traffic flows round them.

1974 to 1983

Network

TCP/IP: one language for every network

By the 1970s there were many separate networks. Vint Cerf and Bob Kahn designed a way to join them: IP gives every computer an address and moves packets between networks, and TCP checks that every packet arrived, in order, and asks again for any that went missing.

IP address: 192.0.2.17

1974

Cerf and Kahn publish their design for joining networks together.

1 January 1983

“Flag day”: ARPANET switches to TCP/IP. Computers that had not changed over were cut off.

Today

Every device on the internet still speaks IP, from a phone to a fridge.

A network of networks is what the word internet means. Flag day is a rare case of everyone switching at once, and it worked only because the network was still small, a few hundred computers.

1983

Network

DNS: names instead of numbers

People remember names, and computers route by numbers. In 1983 Paul Mockapetris designed the Domain Name System, which turns a name into an address.

No single computer holds every name. Each level knows who to ask next.

looking up www.example.ie

1 root: ask the .ie servers
2 .ie: ask example.ie’s servers
3 example.ie: www is 192.0.2.17

then the browser connects to 192.0.2.17

Your computer remembers answers for a while, so most lookups take a few milliseconds.

DNS is the first step of almost every visit to a website, and when it breaks, sites seem to vanish even though their servers are fine. Each answer carries a time to live, which says how long it can be remembered.

Chapter 2 · 1991 to 1999

The web over a phone line

Most people reached the web through a modem that turned data into sound on a telephone line. Every byte counted.

Network

HTML

This chapter shows the network shaping the page. Designers built for slow, noisy connections, and the protocol itself grew up to make each connection go further.

1991 to 1997

Network

Server

HTTP: the web’s own protocol

HTTP is the protocol a browser and a web server use. It runs on top of TCP, so it can assume every byte arrives.

GET /index.html HTTP/1.1
Host: www.example.ie

1991 · HTTP/0.9

One line: GET and a path. The answer was HTML and nothing else.

1996 · HTTP/1.0

Adds status codes such as 404, and headers that describe the content, so images could travel too.

1997 · HTTP/1.1

Keeps a connection open for several requests, and adds the Host header, so one server could hold many sites.

The Host header changed the business of the web. Before it, every site needed its own IP address. After it, one cheap server could host hundreds of small sites, which is what made shared hosting so cheap.

Pages were built for that wait: small GIF images, few colours, text that appeared first, and images that loaded in coarse stripes, then sharpened.

The alt text on an image was often what a visitor read while the picture arrived, or instead of it.

Times are the nominal speed and ignore overheads, so real pages took longer.

To work out a time: kilobytes times 8 gives kilobits, then divide by the speed. 100 times 8 is 800 kilobits, and 800 divided by 14.4 is about 56 seconds. The 56k standard, V.90, was agreed in 1998. A modem also tied up the phone line, so nobody could ring the house while someone was online.

1995 to 1999

Network

Server

A lock for the connection

SSL, 1995

Netscape added SSL to its browser so that a connection could be encrypted. A card number could now cross the internet without anyone on the way reading it.

https:// and a padlock

TLS, 1999

The standards body took SSL over and renamed it TLS. Every padlock in a browser today is TLS.

Encryption made online shopping possible. For years it was slow and expensive, so only the payment pages used it.

Encryption costs a little time at the start of each connection, for the two computers to agree on keys. On 1990s hardware that cost was large, which is why sites encrypted only the pages that needed it. Chapter 5 shows how that changed.

Chapter 3 · 1998 to 2007

Always on

Broadband and Wi-Fi left the connection open all day. Sites could send more, more often, to more places.

Network

Server

The shift from dialling in to always on changed habits as much as speed. People checked a site many times a day, and sites began to update themselves.

About 1999 to 2005

Network

Scripts

Broadband changes what a page can do

Always on

DSL over phone lines and cable modems over TV cables gave connections that stayed open, at a megabit or more.

Scripts in the background

With the connection always there, a page could ask the server for small updates every few seconds. That is the Ajax pattern of 2005.

Gmail, 2004 · Google Maps, 2005

Video

YouTube launched in 2005. Streaming video to anyone needed both broadband homes and cheap bandwidth for the server.

Each of these was possible earlier in a lab. Broadband made it possible for ordinary visitors.

Ask the class to imagine Google Maps on a 28.8 modem: every drag of the map fetches new image tiles. The design only works when fetching is cheap and quick.

1997 to 2003

Network

Wi-Fi cuts the cable

Wi-Fi carries network packets over radio. The standard is called 802.11, and the name Wi-Fi came from the industry group that tested devices against it.

A laptop could now be online anywhere in a building, and soon in cafés, stations and airports.

1997

The first 802.11 standard, at 2 Mbit/s.

1999

802.11b reaches 11 Mbit/s, and the Wi-Fi Alliance forms to certify devices.

2003

Laptops start to include Wi-Fi as standard.

Radio is shared and noisy, so Wi-Fi spends much of its time on taking turns and resending lost packets. That is why it feels slower than its headline speed, and why a busy café network crawls.

1998 onwards

Network

Server

Content delivery networks: copies near the reader

The problem

Light in fibre needs at least 80 milliseconds to cross from Dublin to San Francisco and back. A page with many files makes that trip many times.

The fix

A content delivery network keeps copies of a site’s images, styles and scripts on servers in many cities, and answers each visitor from the nearest one. Akamai, founded in 1998, was the first big one.

Dublin visitor → Dublin copy, not California

Distance became a design problem. Bandwidth can grow, but nothing makes light faster.

This is the first big change to the shape of a site: the origin server keeps the data and the pages, and copies of the heavy files live all over the world. Most large sites, and many small ones, now sit behind a CDN.

Chapter 4 · 2007 to 2014

The web in your pocket

Phones put the web on slow, patchy radio links, and the same pages had to work on all of them.

Network

Scripts

Mobile networks brought the web to billions of people, often as their only connection. They also brought high latency and dropped signals, which changed how pages had to be built.

2001 to 2009

Network

CSS

Mobile data grows up

The first iPhone, in 2007, showed full web pages on a phone, over a 2G network called EDGE at well under a megabit.

Mobile networks add latency, the delay before anything arrives. A phone often waits hundreds of milliseconds for the first byte, however fast the download.

2001

The first 3G network opens, in Japan.

2008

The iPhone 3G brings faster mobile data to a mass audience.

14 December 2009

The first commercial 4G LTE networks open in Stockholm and Oslo.

Two ideas to keep apart. Bandwidth is how much arrives each second, like the width of a pipe. Latency is how long the first drop takes to arrive, like the length of the pipe. Mobile improved bandwidth faster than latency.

2011

Network

Scripts

WebSocket: a line that stays open

Ajax asks, the server answers, and the line closes. For a chat or a live score, a page had to keep asking “anything new?” every few seconds.

WebSocket, standardised in 2011, keeps one connection open in both directions, so the server can send news the moment it happens.

in the browser

const socket = new WebSocket(
"wss://chat.example.ie");

socket.onmessage = (event) => {
showMessage(event.data);
};

Polling sends hundreds of empty questions. A socket sends only the answers.

Live chat, shared documents and multiplayer games in the browser rely on this. On a phone it also saves battery, because the radio wakes up only when there is news.

2010 onwards

Network

HTML

CSS

Designing for the slowest likely connection

Responsive images

HTML gained ways to offer several sizes of an image, so a phone downloads a small one.

<img srcset="small.jpg 480w, big.jpg 1600w">

Lazy loading

Images further down the page wait until the reader scrolls near them.

<img loading="lazy">

Mobile first

Designers start from the phone layout and add to it for wide screens.

The network had become part of the design brief.

Each of these saves bytes on a slow or metered connection. Lazy loading became a plain HTML attribute from 2019, as browsers added it one by one; before that it needed a script.

Chapter 5 · 2015 to 2022

Faster, and encrypted by default

The protocols themselves were rebuilt: more requests at once, quicker handshakes, and a new transport for mobile.

Network

For twenty years HTTP barely changed. Between 2015 and 2022 it changed twice, and encryption went from optional to normal.

May 2015

Network

HTML

HTTP/2: many requests on one connection

HTTP/1.1

Browsers opened about six connections to a site and sent one request at a time on each. Pages with a hundred files waited in queues.

1 · 2 · 3 · 4 · 5 · 6, then wait

HTTP/2

Many requests travel together on one connection, interleaved. Nothing waits for a slow file in front of it.

all at once, on one line

Old speed tricks, such as joining every image into one big sprite sheet, stopped being necessary.

HTTP/2 grew from SPDY, an experiment Google began in 2009. It is a good example of a technology moving from one company's test into a shared standard. The request and response look the same to a web developer; only the way they travel changed.

2015 to 2018

Network

Server

Encryption becomes the default

Free certificates from Let’s Encrypt, from December 2015, removed the cost of HTTPS. Browsers then began to warn about every plain HTTP page.

TLS 1.3, in August 2018, cut the handshake from two round trips to one, so encryption barely slows the start of a visit.

2015

Let’s Encrypt opens to the public with free certificates.

2018

TLS 1.3 is published. Chrome marks plain HTTP as “Not secure”.

2025

About 88 per cent of sites send visitors to HTTPS by default.

The 2025 figure comes from W3Techs. Encryption also hides which page on a site someone reads, from anyone on the same network. It does not hide which site they visit.

2021 and 2022

Network

HTTP/3: a new road for mobile

TCP delivers bytes strictly in order, so one lost packet holds up everything behind it. On a patchy mobile signal that happens often.

QUIC, standardised in May 2021, replaces TCP for the web. It runs over UDP, a simpler protocol, and handles each stream on its own, so one loss holds up only its own stream. HTTP/3, in June 2022, is HTTP over QUIC.

2013

Google starts testing QUIC in Chrome.

May 2021

QUIC becomes a standard.

June 2022

HTTP/3 becomes a standard.

QUIC also survives a change of network. A phone that walks out of Wi-Fi onto 4G can keep the same connection, where TCP would have to start again.

2019 onwards

Network

5G, fibre and Wi-Fi 6

The last mile got much faster in the late 2010s. Fibre to the home, 5G mobile and Wi-Fi 6 all arrived within a few years of each other.

Headline speeds now reach a gigabit or more. The web did not need that speed for pages; video, games and large downloads used it.

April 2019

The first 5G phone networks open, in South Korea and the United States.

2019

Wi-Fi 6 devices arrive.

2020s

Fibre replaces copper phone lines in many homes.

The pattern from chapter 3 repeats: a faster pipe arrives, and new uses fill it. Ask the class what they do on a phone now that would have been impossible in 2010.

Chapter 6 · 2014 to now

Heavier pages, uneven networks

Pages grew as fast as connections did, and a third of the world is still not online.

Network

HTML

This chapter turns the story round. Faster networks did not make the web fast for everyone, because pages grew to fill them, and many people still have slow connections or none.

2014 to 2024

HTML

Network

Pages grew to fill the pipe

Median page on a phone, 2014

505 KB

Median page on a phone, 2024

2,311 KB

Source: HTTP Archive, Web Almanac 2024

The median page on a phone grew more than four times over in ten years. Most of the weight is images and scripts.

That 2024 page would take about 5½ minutes on a 1998 modem, and about a second on good 4G.

The arithmetic: 2,311 kilobytes is about 18,500 kilobits, and at 56 kilobits a second that is about 330 seconds. On a 20 megabit 4G link it is just under a second. Desktop pages grew from 1,208 KB to 2,652 KB over the same years. The point is not that pages should be tiny; it is that every byte is paid for by someone on a slow or metered connection.

2024

Network

Who is still offline?

Online

About 5.5 billion people used the internet in 2024, 68 per cent of the world’s population.

Offline

About 2.6 billion people did not. Most live in low-income countries and rural areas.

Slow and metered

Many people online pay for each gigabyte, or share one phone in a household.

Source: International Telecommunication Union, Facts and Figures 2024.

The S-curve from the start of the talk has not reached the top, and it is flattening slowly. A site that loads in a second in Dublin may take a minute, and cost real money, somewhere else. Satellite services and cheaper phones are pushing the curve up, but the gap is still large.

2017 onwards

Network

Server

The server moves towards the reader

Edge functions

CDNs began to run small programs, not only to store copies. A request can be answered in the nearest city without reaching the main server.

Caching rules

Headers tell every browser and CDN how long a file may be kept, so most visits download only what changed.

Cache-Control: max-age=31536000

The architecture keeps shifting to beat distance: data in one place, code and copies near every reader.

This is chapter 3's content delivery network grown up. It also brings back an old question in a new form: if a page is built in two hundred cities, which copy is the true one, and how quickly do the others hear about a change?

Chapter 7 · Today

Putting it together

What happens between pressing Enter and seeing a page, and the habits that keep a site fast on every network.

Today

Network

HTML

What happens when you press Enter

1

DNS

The name becomes an IP address.

2

Connect

TCP or QUIC opens a connection to that address.

3

Encrypt

TLS agrees keys, so nobody can read the traffic.

4

Request

HTTP asks for the page, and the server answers.

5

Render

The browser builds the page, then fetches its images, styles and scripts.

On a good connection all five take well under a second. On a slow mobile link, steps 1 to 3 alone can take a second, before a single byte of the page arrives.

Name the chapter each step came from: DNS from chapter 1, TCP from chapter 1 and QUIC from chapter 5, TLS from chapters 2 and 5, HTTP from chapter 2, and the many extra files from chapter 6. Every browser can show this sequence: open the developer tools, choose the Network tab and reload, then hover over the timing bar of the first request.

HTML

Server

Five habits for every network

Weigh the page

Check the total size in the developer tools. Images are usually the heaviest part.

Right-size images

Serve small images to small screens, in modern formats.

Load lazily

Let images and scripts below the fold wait.

Cache

Tell browsers and CDNs how long files can be kept.

Test slow

Throttle the connection in the developer tools and watch the page load.

Each habit answers a constraint from this history: the modem, the phone, the distance, and the page that grew.

Every browser's developer tools can pretend to be a slow 3G phone. Trying a site that way for a minute teaches more than any rule.
