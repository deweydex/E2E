Before we start: history is messy

The dates on this page mark when something appeared, not when everyone used it. In 1962 the sociologist Everett Rogers described how new ideas spread: a few innovators first, then early adopters, the majority, and last of all the laggards. Add them up and the total follows an S-curve, slow, then steep, then flat.

The share of the world’s people online follows the same S-curve, and it has not reached the top.

  • A real S-curve. Under 1 per cent of people were online in 1995, 16 per cent in 2005 and 67 per cent in 2023.
  • Not finished. About 2.6 billion people were still offline in 2024, so the curve is still climbing.
  • Overlap. HTTP/2 reached about half of all sites in 2021, then fell to about a third by 2025 as HTTP/3 took over, while older sites kept HTTP/1.1.

Sources: World Bank and ITU, internet users per 100 people; ITU Facts and Figures 2024; W3Techs, HTTP/2 and HTTP/3 usage. Rogers, Diffusion of Innovations (1962).

The Wire Gets Wider

This page is a history of the networks and protocols under the web, and of how each faster, wider pipe changed what a website could be. It rebuilds itself as you scroll, in the look of each way people got online, from a teleprinter to the phone in your pocket.

  • Network the wires, radios and protocols
  • Server the computer that answers
  • HTML the page that travels
  • Scripts code that opens connections

29 October 1969: the first message Network

A student at UCLA tried to log in to a computer at Stanford Research Institute over ARPANET, a new network funded by the US Department of Defense. The system crashed after two letters, so the first message was "LO". The idea behind ARPANET was packet switching: cut each message into small packets, let each one find its own route, and put them back in order at the far end.

Packets will be listed here as they arrive.

1974 to 1983: TCP/IP Network

Vint Cerf and Bob Kahn designed a way to join separate networks into one internet. IP gives every computer an address and moves packets between networks. TCP checks that every packet arrived, in order, and asks again for any that went missing. On 1 January 1983, "flag day", ARPANET switched to TCP/IP all at once.

1983: DNS, names instead of numbers Network

People remember names, and computers route by numbers. Paul Mockapetris designed the Domain Name System, which turns a name into an address. No single computer knows every name, so each level points to the next.

1991 to 1997: HTTP, the web's own protocol Network Server


HTTP is how a browser and a web server talk. It runs on top of TCP, so it can assume every byte arrives.




VersionWhat it added


HTTP/0.9, 1991One line, GET /page, and the answer was HTML only.


HTTP/1.0, 1996Status codes such as 404, and headers that describe the content, so images could travel too.


HTTP/1.1, 1997Connections kept open for several requests, and the Host header, so one server could hold many sites.




The Host header changed the business of the web. Before it, every site needed its own IP address. After it, one cheap server could host hundreds of small sites, which made shared hosting cheap.

1995 to 1999: a lock for the connection Network


Netscape added SSL to its browser in 1995 so that a connection could be encrypted, and a card number could cross the internet without anyone on the way reading it. In 1999 the standards body took it over and renamed it TLS. Encryption was slow on the computers of the time, so for years only payment pages used it.

Always on Network Scripts


From about 1999, DSL over phone lines and cable modems over TV cables gave homes connections that stayed open all day at a megabit or more. That changed what a page could do. A script could ask the server for small updates every few seconds, which is the Ajax pattern behind Gmail in 2004 and Google Maps in 2005. YouTube launched in 2005, because streaming video to anyone needed broadband homes and cheap bandwidth.






Wi-Fi cuts the cable  Network


Wi-Fi carries packets over radio. The 802.11 standard appeared in 1997 at 2 Mbit/s, 802.11b reached 11 Mbit/s in 1999, and laptops began to include Wi-Fi as standard around 2003. Radio is shared and noisy, so Wi-Fi spends much of its time taking turns and resending lost packets, which is why a busy café network crawls.






Content delivery networks: copies near the reader Network Server


Light in fibre needs at least 80 milliseconds to go from Dublin to San Francisco and back, and a page with many files makes that trip many times. A content delivery network keeps copies of a site's heavy files in many cities. Akamai, founded in 1998, was the first big one. Pick where the reader is, then compare.


     







How this part is built: soft gradients, rounded boxes and glossy green buttons, as on mid-2000s sites. The round-trip times are worked out from the straight-line distance and the speed of light in glass, about 200,000 km a second, so real routes are slower.














Mobile data grows up Network


The first iPhone, in 2007, showed full web pages over a slow 2G network. The first 3G network had opened in Japan in 2001, and the first commercial 4G LTE networks opened in Stockholm and Oslo on 14 December 2009. Mobile networks add latency: a phone often waits hundreds of milliseconds before the first byte arrives, however fast the download. Bandwidth is the width of the pipe; latency is its length.

May 2015: HTTP/2, many requests on one connection Network


With HTTP/1.1, a browser opened about six connections to a site and sent one request at a time on each, so a page with many files waited in queues. HTTP/2 sends many requests together on one connection, interleaved. Load the same twelve files both ways. Orange is time spent waiting in a queue.

Encryption becomes the default Network Server


Free certificates from Let's Encrypt, from December 2015, removed the cost of HTTPS, and browsers began to warn about plain HTTP pages. TLS 1.3, in August 2018, cut the encryption handshake from two round trips to one. By 2025, about 88 per cent of sites sent visitors to HTTPS by default.






2021 and 2022: QUIC and HTTP/3 Network


TCP delivers bytes strictly in order, so one lost packet holds up everything behind it, and on a patchy phone signal that happens often. QUIC, standardised in May 2021, runs over UDP and handles each stream on its own. HTTP/3, in June 2022, is HTTP over QUIC. It also survives a change of network, so a phone walking out of Wi-Fi onto 4G keeps the same connection.






2019 onwards: 5G, fibre and Wi-Fi 6 Network


The first 5G phone networks opened in April 2019, in South Korea and the United States. Fibre to the home and Wi-Fi 6 arrived in the same few years. Headline speeds reached a gigabit or more, and video, games and large downloads filled them.




How this part is built: flat cards with a soft shadow, Roboto and a teal app bar, as in the Material Design years. The timings use a made-up 100 ms per file and a limit of six connections for HTTP/1.1, so compare the shapes rather than the numbers.












Pages grew to fill the pipe HTML Network

Who is still offline? Network


In 2024, about 5.5 billion people used the internet, 68 per cent of the world's population. About 2.6 billion did not, most of them in low-income countries and rural areas. Each dot below is one per cent of the world.




Many people who are online pay for each gigabyte, or share one phone in a household. A site that loads in a second in Dublin may take a minute, and cost real money, somewhere else.



The server moves towards the reader Server Network


From about 2017, content delivery networks began to run small programs as well as store copies, so a request can be answered in the nearest city. Headers such as Cache-Control: max-age=31536000 tell every browser and CDN how long a file may be kept, so a returning visitor downloads only what changed.


How this part is built: plain bars sized with percentages, a grid of a hundred dots for the world, and a few lines of arithmetic: kilobytes times 8, divided by the speed in kilobits a second, plus the latency of each network.












What happens when you press Enter Network Server HTML


Five steps happen before you see a page, and the first three are about the network alone. Choose a connection and step through them. Each step costs one or more round trips, the time for a message to reach the server and an answer to come back.

Five habits for every network Network HTML




Weigh the page
Check its total size in the browser's developer tools. Images are usually the heaviest part.


Right-size images
Serve small images to small screens, in modern formats.


Load lazily
Let images and scripts further down the page wait.


Cache
Tell browsers and CDNs how long each file can be kept.


Test slow
Throttle the connection in the developer tools and watch the page load.




How this part is built: with today's HTML and CSS, light or dark to match your device. The step times are round trips multiplied out; real visits add server time, and often reuse a connection or a remembered DNS answer to skip the first steps.
