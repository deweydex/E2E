Down the Wire

Notes on a history of the networks and protocols under the web, and of how each faster, wider pipe changed what a website could be. The headings follow the slides in order, and each section reads on its own.

Introduction

Down the Wire

Every page, script and database query travels over a network. These notes follow the wires, radios and rules that carry them, from a two-letter message in 1969 to 5G. The thread through the story is simple: each time the pipe got wider or faster, websites changed shape to fill it.

The road under every request

Each section carries a coloured tag for every part of a website it is about, with the name written on it, so nobody has to rely on colour alone.

HTML is the page itself, which has to travel to the reader.
CSS is the look of the page, sent alongside it.
Scripts are code in the browser that opens connections and sends requests.
Server is the computer at the other end that answers.
Network is the wires, radios and agreed rules that carry every byte between them.

The agreed rules are called protocols: agreements about how two machines talk. Most of this history is about the network, and the other parts appear where a change in the network changed what pages, scripts or servers could do.

The network is older than the web by twenty years, so the story starts in 1969. Chapters overlap, because new networks arrived in some places years before others.

Before we start: history is messy

The dates in these notes mark when something appeared or became a standard. They do not mark when everyone used it. Every technology here spread at its own speed, overlapped with older ones for years, and depended on others that came before it.

How a new technology spreads

In 1962 the sociologist Everett Rogers described how new ideas spread through a group of people in his book Diffusion of Innovations. He sorted people into five groups by when they take up something new.

GroupShareWho they are
Innovators2.5%Try something while it is still rough and risky
Early adopters13.5%Take it up once it shows promise, and others watch them
Early majority34%Wait until it works reliably
Late majority34%Join once most people already use it
Laggards16%Switch last, often only when the old way stops working

The bell curve shows how many people adopt in each period. Add them up, and the total so far follows an S-curve: slow at first, then steep, then flat. The percentages are idealised, and real technologies rarely follow the shape exactly.

Chapter 1 · 1969 to 1990: Packets find their way

Before the web, researchers built a network that could carry any message, by any route, between any computers. Packets, addresses and names, the ideas in this chapter, were not built for the web, which arrived twenty years later.

The first message, and the idea of a packet Network

A telephone call holds one line open for the whole conversation. Packet switching works differently: a message is cut into small packets, each packet carries the address it is going to, and each can take any free route there. The receiver puts them back in order.

HELLO  →  [H] [E] [L] [L] [O]  →  each by its own route  →  HELLO

On 29 October 1969 a student in Leonard Kleinrock's lab at UCLA tried to log in to a computer at Stanford Research Institute over ARPANET, a network funded by the US Department of Defense. The system crashed after two letters, so the first message was "LO". By the end of 1969 the network linked four universities. Because packets share the lines, a broken link only means a different route, which is why the internet keeps working around faults.

TCP/IP: one language for every network Network

By the 1970s there were many separate networks. Vint Cerf and Bob Kahn designed a way to join them.

  • IP gives every computer an address, such as 192.0.2.17, and moves packets between networks.
  • TCP checks that every packet arrived, in order, and asks again for any that went missing.
  • 1974. Cerf and Kahn publish their design for joining networks together.
  • 1 January 1983. "Flag day": ARPANET switches to TCP/IP. Computers that had not changed over were cut off.
  • Today. Every device on the internet still speaks IP, from a phone to a fridge.

A network of networks is what the word internet means. Flag day is a rare case of everyone switching at once, and it worked only because the network was still small, a few hundred computers.

DNS: names instead of numbers Network

People remember names, and computers route by numbers. In 1983 Paul Mockapetris designed the Domain Name System, which turns a name into an address. No single computer holds every name. Each level knows who to ask next:

looking up www.example.ie
1  root:        ask the .ie servers
2  .ie:         ask example.ie's servers
3  example.ie:  www is 192.0.2.17

then the browser connects to 192.0.2.17

Your computer remembers each answer for a while, set by a "time to live", so most lookups take a few milliseconds. DNS is the first step of almost every visit to a website, and when it breaks, sites seem to vanish even though their servers are fine.

When the web began, the network built in chapter 1 reached under 1 per cent of the world. The climb took thirty years.

Chapter 2 · 1991 to 1999: The web over a phone line

Most people reached the web through a modem that turned data into sound on a telephone line, and every byte counted. In this chapter the network shapes the page, and the protocol grows up to make each connection go further.

HTTP: the web’s own protocol Network Server

HTTP is the protocol a browser and a web server use. It runs on top of TCP, so it can assume every byte arrives.

GET /index.html HTTP/1.1
Host: www.example.ie
VersionWhat it added
HTTP/0.9, 1991One line: GET and a path. The answer was HTML and nothing else.
HTTP/1.0, 1996Status codes such as 404, and headers that describe the content, so images could travel too.
HTTP/1.1, 1997A connection kept open for several requests, and the Host header, so one server could hold many sites.

The Host header changed the business of the web. Before it, every site needed its own IP address. After it, one cheap server could host hundreds of small sites, which is what made shared hosting so cheap.

How long did a page take? Network HTML

ConnectionSpeedA 100 KB page
Modem, about 199414.4 kbit/sabout 56 s
Modem, about 199628.8 kbit/sabout 28 s
56k modem, 199856 kbit/sabout 14 s
Early broadband, 20021 Mbit/sunder 1 s

To work out a time, multiply kilobytes by 8 to get kilobits, then divide by the speed. 100 × 8 is 800 kilobits, and 800 ÷ 14.4 is about 56 seconds. These are nominal speeds that ignore overheads, so real pages took longer. The 56k standard, V.90, was agreed in 1998. A modem also tied up the phone line, so nobody could ring the house while someone was online.

Pages were built for that wait: small GIF images, few colours, text that appeared first, and images that loaded in coarse stripes, then sharpened. The alt text on an image was often what a visitor read while the picture arrived, or instead of it.

A lock for the connection Network Server

SSL, 1995. Netscape added SSL to its browser so that a connection could be encrypted, and a card number could cross the internet without anyone on the way reading it. The address began with https:// and the browser showed a padlock.

TLS, 1999. The standards body took SSL over and renamed it TLS. Every padlock in a browser today is TLS.

Encryption made online shopping possible. It costs a little time at the start of each connection, for the two computers to agree on keys, and on 1990s hardware that cost was large. For years only payment pages used it.

How fast did it spread?

In 2000 half of US adults were online, but only 1 in 100 had broadband: almost everyone else was dialling in.

Chapter 3 · 1998 to 2007: Always on

Broadband and Wi-Fi left the connection open all day, so sites could send more, more often, to more places. The shift from dialling in to always on changed habits as much as speed.

Broadband changes what a page can do Network Scripts

  • Always on. DSL over phone lines and cable modems over TV cables gave connections that stayed open, at a megabit or more.
  • Scripts in the background. With the connection always there, a page could ask the server for small updates every few seconds. That is the Ajax pattern, behind Gmail in 2004 and Google Maps in 2005.
  • Video. YouTube launched in 2005. Streaming video to anyone needed both broadband homes and cheap bandwidth for the server.

Each of these was possible earlier in a lab. Broadband made it possible for ordinary visitors. Imagine Google Maps on a 28.8 modem: every drag of the map fetches new image tiles, so the design only works when fetching is cheap and quick.

Wi-Fi cuts the cable Network

Wi-Fi carries network packets over radio. The standard is called 802.11, and the name Wi-Fi came from the industry group that tests devices against it. A laptop could now be online anywhere in a building, and soon in cafés, stations and airports.

  • 1997. The first 802.11 standard, at 2 Mbit/s.
  • 1999. 802.11b reaches 11 Mbit/s, and the Wi-Fi Alliance forms to certify devices.
  • 2003. Laptops start to include Wi-Fi as standard.

Radio is shared and noisy, so Wi-Fi spends much of its time taking turns and resending lost packets. That is why it feels slower than its headline speed, and why a busy café network crawls.

Content delivery networks: copies near the reader Network Server

Light in fibre travels at about 200,000 km a second, so it needs at least 80 milliseconds to go from Dublin to San Francisco and back. A page with many files makes that trip many times.

A content delivery network keeps copies of a site's images, styles and scripts on servers in many cities, and answers each visitor from the nearest one. Akamai, founded in 1998, was the first big one. This was the first big change to the shape of a site: the main server keeps the data and pages, and copies of the heavy files live all over the world. Bandwidth can grow, but nothing makes light faster.

How fast did it spread?

Chapter 4 · 2007 to 2014: The web in your pocket

Phones put the web on slow, patchy radio links, and the same pages had to work on all of them. Mobile networks brought the web to billions of people, often as their only connection.

Mobile data grows up Network CSS

The first iPhone, in 2007, showed full web pages on a phone, over a 2G network called EDGE at well under a megabit.

  • 2001. The first 3G network opens, in Japan.
  • 2008. The iPhone 3G brings faster mobile data to a mass audience.
  • 14 December 2009. The first commercial 4G LTE networks open in Stockholm and Oslo.

Two ideas need keeping apart. Bandwidth is how much arrives each second, like the width of a pipe. Latency is how long the first drop takes to arrive, like the length of the pipe. A phone often waits hundreds of milliseconds for the first byte, however fast the download, and mobile networks improved bandwidth faster than latency.

WebSocket: a line that stays open Network Scripts

Ajax asks, the server answers, and the line closes. For a chat or a live score, a page had to keep asking "anything new?" every few seconds. That is called polling, and it sends hundreds of empty questions. WebSocket, standardised in 2011, keeps one connection open in both directions, so the server can send news the moment it happens.

const socket = new WebSocket("wss://chat.example.ie");

socket.onmessage = (event) => {
  showMessage(event.data);
};

Live chat, shared documents and multiplayer games in the browser rely on this. On a phone it also saves battery, because the radio wakes up only when there is news.

Designing for the slowest likely connection Network HTML CSS

  • Responsive images. HTML gained ways to offer several sizes of an image, so a phone downloads a small one: <img srcset="small.jpg 480w, big.jpg 1600w">
  • Lazy loading. Images further down the page wait until the reader scrolls near them: <img loading="lazy">. This became a plain HTML attribute from 2019, as browsers added it one by one; before that it needed a script.
  • Mobile first. Designers start from the phone layout and add to it for wide screens.

Each of these saves bytes on a slow or metered connection. The network had become part of the design brief.

Chapter 5 · 2015 to 2022: Faster, and encrypted by default

For twenty years HTTP barely changed. Between 2015 and 2022 it changed twice, and encryption went from optional to normal.

HTTP/2: many requests on one connection Network HTML

With HTTP/1.1, browsers opened about six connections to a site and sent one request at a time on each, so pages with a hundred files waited in queues. HTTP/2, standardised in May 2015, sends many requests together on one connection, interleaved, so nothing waits for a slow file in front of it.

HTTP/1.1   connection 1: [file 1][file 7]
           connection 2: [file 2][file 8]
           …six connections, then wait in line
HTTP/2     one connection: [1][2][3][4][5][6][7][8]… interleaved

Old speed tricks, such as joining every image into one big "sprite sheet", stopped being necessary. HTTP/2 grew from SPDY, an experiment Google began in 2009. The requests and answers look the same to a web developer; only the way they travel changed.

Encryption becomes the default Network Server

Free certificates from Let's Encrypt, from December 2015, removed the cost of HTTPS, and browsers then began to warn about every plain HTTP page. TLS 1.3, in August 2018, cut the handshake from two round trips to one, so encryption barely slows the start of a visit.

  • 2015. Let's Encrypt opens to the public with free certificates.
  • 2018. TLS 1.3 is published. Chrome marks plain HTTP as "Not secure".
  • 2025. About 88 per cent of sites send visitors to HTTPS by default, according to W3Techs.

Encryption hides which page on a site someone reads from anyone on the same network. It does not hide which site they visit.

HTTP/3: a new road for mobile Network

TCP delivers bytes strictly in order, so one lost packet holds up everything behind it. On a patchy mobile signal that happens often. QUIC replaces TCP for the web: it runs over UDP, a simpler protocol, and handles each stream on its own, so one loss holds up only its own stream. HTTP/3 is HTTP over QUIC.

  • 2013. Google starts testing QUIC in Chrome.
  • May 2021. QUIC becomes a standard.
  • June 2022. HTTP/3 becomes a standard.

QUIC also survives a change of network. A phone that walks out of Wi-Fi onto 4G can keep the same connection, where TCP would have to start again.

5G, fibre and Wi-Fi 6 Network

The last mile got much faster in the late 2010s. The first 5G phone networks opened in April 2019, in South Korea and the United States. Wi-Fi 6 devices arrived the same year, and fibre began to replace copper phone lines in many homes. Headline speeds now reach a gigabit or more. Web pages did not need that speed; video, games and large downloads used it. The pattern from chapter 3 repeats: a faster pipe arrives, and new uses fill it.

Chapter 6 · 2014 to now: Heavier pages, uneven networks

Pages grew as fast as connections did, and a third of the world is still not online. Faster networks did not make the web fast for everyone.

Pages grew to fill the pipe HTML Network

Median page weight20142024
On a phone505 KB2,311 KB
On a desktop1,208 KB2,652 KB

The median page on a phone grew more than four times over in ten years, and most of the weight is images and scripts. The 2024 page would take about 5½ minutes on a 1998 modem: 2,311 KB is about 18,500 kilobits, and at 56 kilobits a second that is about 330 seconds. On a 20 megabit 4G link it takes just under a second. The point is not that pages must be tiny. Every byte is paid for by someone on a slow or metered connection.

Source: HTTP Archive, Web Almanac 2024

Who is still offline? Network

  • Online. About 5.5 billion people used the internet in 2024, 68 per cent of the world's population.
  • Offline. About 2.6 billion people did not. Most live in low-income countries and rural areas.
  • Slow and metered. Many people online pay for each gigabyte, or share one phone in a household.

The S-curve from the start of these notes has not reached the top, and it is flattening slowly. A site that loads in a second in Dublin may take a minute, and cost real money, somewhere else.

Source: International Telecommunication Union, Facts and Figures 2024

The server moves towards the reader Network Server

  • Edge functions. From about 2017, content delivery networks began to run small programs, not only to store copies. A request can be answered in the nearest city without reaching the main server.
  • Caching rules. Headers tell every browser and CDN how long a file may be kept, so most visits download only what changed: Cache-Control: max-age=31536000 means "keep this for a year".

The architecture keeps shifting to beat distance: data in one place, code and copies near every reader. That brings back an old question in a new form: if a page is built in two hundred cities, which copy is the true one, and how quickly do the others hear about a change?

How fast did it spread?

Mobile reached the world far faster than wires did, but in 2024 about a third of people were still offline.

Chapter 7 · Today: Putting it together

What happens between pressing Enter and seeing a page, and the habits that keep a site fast on every network.

What happens when you press Enter Network Server HTML

StepWhat happensRound tripsFrom chapter
1 DNSThe name becomes an IP address.1, unless remembered1
2 ConnectTCP or QUIC opens a connection to that address.1 (QUIC shares it with step 3)1 and 5
3 EncryptTLS agrees keys, so nobody can read the traffic.12 and 5
4 RequestHTTP asks for the page, and the server answers.1, plus server time2
5 RenderThe browser builds the page, then fetches its images, styles and scripts.1 or more6

A round trip is the time for a message to reach the server and an answer to come back. On home broadband that might be 40 milliseconds, so the five steps cost about a quarter of a second. On a weak 3G link it might be 300 milliseconds, and steps 1 to 3 alone take about a second before a single byte of the page arrives. Every browser can show this sequence: open the developer tools, choose the Network tab and reload, then hover over the timing bar of the first request.

Five habits for every network Network HTML Server

HabitWhat to do
Weigh the pageCheck the total size in the developer tools. Images are usually the heaviest part.
Right-size imagesServe small images to small screens, in modern formats.
Load lazilyLet images and scripts further down the page wait.
CacheTell browsers and CDNs how long each file can be kept.
Test slowThrottle the connection in the developer tools and watch the page load.

Each habit answers a constraint from this history: the modem, the phone, the distance, and the page that grew.
