Before we start: history is messy

The dates on this page mark when something appeared, not when everyone used it. In 1962 the sociologist Everett Rogers described how new ideas spread: a few innovators first, then early adopters, the majority, and last of all the laggards. Add them up and the total follows an S-curve, slow, then steep, then flat.

Real technologies are untidier than the curve. This chart comes from one survey of the top ten million websites, so the lines can be compared.

  • Overlap. PHP is from 1995, and three sites in four still ran it in 2025.
  • Different speeds. Node arrived in 2009 but reached 4 per cent of sites only in 2025.
  • Dependency. A change of language means rewriting a working site, so servers change far more slowly than browsers.

Source: W3Techs surveys of the top ten million websites, 1 January each year. Rogers, Diffusion of Innovations (1962).

The Server Remembers

This page is a history of the web told from behind the page: the programs that answer requests and the databases that remember. It rebuilds itself as you scroll, in the look of each era's machines, from a green screen in the 1970s to the browser you are using now.

Five tags mark what each idea belongs to:

  • HTML the page the server sends back
  • CSS the look of that page
  • Scripts code in the browser that sends requests

1966 to 1970: data lived in trees Database

Banks and airlines needed computers that remembered things long before the web existed. IBM's IMS, built in the late 1960s for the Apollo space programme, stored data as a tree. A customer held orders, and each order held items. A program found data by walking down the tree, one level at a time.

1970: Codd puts everything in tables Database

In June 1970 Edgar F. Codd, a mathematician at IBM, published A Relational Model of Data for Large Shared Data Banks. Every fact goes in a table of rows and columns, and a key in one table points at a row in another. You say what you want, and the database works out how to find it.

Ask both systems the same question below: which items cost less than 1.00?

1974 to 1986: SQL, one language for asking Database


Researchers at IBM wrote a language for Codd's tables, first called SEQUEL and later SQL. In 1979 the company that became Oracle sold the first commercial SQL database. SQL became an official standard in 1986, so the same language works across products. Fifty years on, the line on the right above still runs, almost unchanged, in every SQL database.

1990: a server is a program that listens Server HTML


Tim Berners-Lee wrote the first web server at CERN in 1990. It waited on a network port for a request, found the matching file on its disk and sent it back. When the file was missing, it answered with a status code instead. 404 still means "Not Found".


Type a path and send a request to this pretend server. It holds two files: /index.html and /about.html.


  





1993: CGI, the server runs a program Server


The Common Gateway Interface, from NCSA in 1993, let a server run a program and send back whatever that program printed. A form could now send data to a script, often written in Perl, and the page did not exist until somebody asked for it. Pages built this way are called dynamic.




  




#!/usr/bin/perl
print "Content-Type: text/html\n\n";
print "<h1>Hello, $name</h1>";



1995: Apache, and the server log Server


In 1995 a group of webmasters gathered their fixes to the NCSA server and released them as Apache. Like most servers, Apache writes one line to a log for every request. Each request you sent above has a line here: who asked, when, the method and path, the status code, and the size of the answer in bytes.






How this part is built: black on white, a serif font, a horizontal rule, and no styling of its own, like the plain pages early servers produced. A script plays the server's part: it matches the path, picks a status code and writes a log line in Apache's Common Log Format.

1995 to 1998: a free stack for everyone Server Database


PHP and MySQL were both released in 1995. Run them on Linux with Apache, and every part of a database-backed site was free. A German magazine named the four together LAMP in 1998. Shared hosting cost a few euro a month, so blogs, forums and shops could all keep their data in a database. PostgreSQL, the other big free database, took its name in 1996.

1994 onwards: how the server remembers you Server


HTTP forgets each request the moment it ends. From 1994 a server could hand the browser a small cookie, and the browser sent it back with every later request. The cookie holds only an id. The server keeps the details, such as who you are and what is in your basket, in a session.

1998: SQL injection Server Database


In 1998 a researcher called rain.forest.puppy described how text typed into a form could change the SQL a server ran. The cause is building a query by gluing strings together. 2004 and 2005: frameworks and the ORM Server Database


Ruby on Rails in 2004 and Django, in Python, in 2005 gave every new site the same folders, routes and database setup. An ORM, an object-relational mapper, lets the program treat rows as objects, and the framework writes the SQL. Migrations change the tables step by step, so every copy of a site has the same structure.




What you write
# Django
Product.objects.filter(price__lt=1)


The SQL it sends
SELECT * FROM products
WHERE price < 1;




An ORM saves typing and guards against injection. It also hides the SQL, so a slow query can go unnoticed.



2003: caching, remember the answer Server


A popular page asked the database the same question thousands of times a minute. memcached, written in 2003 for the LiveJournal blog site, kept recent answers in memory. The server checks the cache first and asks the database only on a miss.

2006 to 2009: NoSQL, bigger with fewer rules Database


Google described Bigtable in 2006 and Amazon described Dynamo in 2007: databases spread over thousands of machines. To grow that big, they gave up some of what SQL databases promise, such as joins between tables. In 2009 a meetup in San Francisco gave the movement a name, NoSQL, and MongoDB and Redis were both released that year.

2006: renting servers by the hour Server Database


Before 2006, a company that wanted a server bought one and kept it running. A busy day meant buying more, and a quiet month left them idle. In March 2006 Amazon began renting storage with S3, and in August it began renting whole virtual servers by the hour with EC2. Google, Microsoft and others followed. 2013 and 2014: containers Server


A container packs a program together with everything it needs to run, so it runs the same way on a laptop and in a data centre. Docker made containers easy in 2013, and in 2014 Google released Kubernetes, which runs many containers across many machines and restarts any that fail. The boxes above are containers.

2014: serverless, just the function Server


AWS Lambda, announced in November 2014, runs one function each time a request arrives, and nothing runs between requests. Choose Serverless above and the purple boxes appear only while requests arrive. There are still servers, of course. Somebody else looks after them.

Meaning as a list of numbers Database


An embedding turns a piece of text into a list of numbers, called a vector. Texts with similar meanings get similar vectors, so a database can find the rows closest in meaning to a question even when they share no words with it. Real embeddings hold hundreds or thousands of numbers. The map below uses only two, so each note can sit at a point on a page.

Look it up, then answer Database Server


A language model knows only what was in its training data. To answer questions about your own documents, a server first finds the nearest notes in a vector database, then hands them to the model along with the question. Researchers at Facebook AI named this retrieval-augmented generation, or RAG, in 2020. It is a three-tier application in disguise: the browser asks, a server program decides, and a database remembers.



The servers' new visitors Server

Five habits that keep a server safe Server Database




Parameters
Never glue input into SQL. Send it as a parameter. (1998)


Hashes
Store a slow hash of each password, never the password itself.


Check again
Check every request on the server, even if the page checked it first.


HTTPS
Encrypt every request, so nobody can read or change it on the way.


Updates
Install security updates promptly. (2017)

SQL is still here Database


SQLite, first released in 2000, keeps a whole SQL database in one file. It is in every phone and every web browser, and it is probably the most used database in the world. The free databases of 1995, PostgreSQL and MySQL, still run a large share of the web, now with JSON and vector features added.
