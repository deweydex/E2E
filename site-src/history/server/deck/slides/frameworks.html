Frameworks and the ORM

Ruby on Rails in 2004 and Django, in Python, in 2005 gave every new project the same folders, routes and database setup.

An ORM, an object-relational mapper, lets the program treat rows as objects. The framework writes the SQL.

the same question, twice

# with an ORM (Django)
Product.objects.filter(price__lt=1)

# the SQL it writes for you
SELECT * FROM products
WHERE price < 1;

An ORM saves typing and guards against injection. It also hides the SQL, so slow queries can go unnoticed.

Migrations also came with these frameworks: small files that change the database’s tables step by step, so every copy of the project has the same structure. Laravel later brought the same ideas to PHP.
