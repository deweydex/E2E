Caching: remember the answer

The problem

A popular page asked the database the same question thousands of times a minute.

The fix

memcached, written in 2003 for the LiveJournal blog site, kept recent answers in memory. The server checks the cache first and asks the database only when the cache has nothing.

cache hit: fast · cache miss: ask the database

A cache trades freshness for speed. The hard part is knowing when a remembered answer has gone out of date.

There is an old joke that the two hardest problems in computing are naming things and cache invalidation. Browsers cache too, which is why a hard refresh sometimes fixes a page.
